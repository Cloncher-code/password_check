# Инструкция 2. Руководство разработчика: разобраться в коде и переделать под себя

Для кого: разработчик, который получил проект и хочет понять, как он устроен, поменять правила или добавить функцию.

Перед началом: проект запускается по инструкции 1, `pytest` зелёный.

## 1. Карта проекта

```
app/
  config.py     ← ВСЕ правила: баллы, пороги, чёрный список, тексты, ошибки, генерация
  scoring.py    ← оценка пароля: validate() → evaluate(). Чистые функции, без FastAPI
  generator.py  ← generate(length): случайный пароль, который получает 100 баллов
  schemas.py    ← Pydantic-модели запроса и ответа API (контракт СТ §6)
  main.py       ← FastAPI: роуты, обработчики ошибок, заголовки безопасности
templates/index.html  ← страница (Jinja2): форма + блок результата
static/style.css      ← оформление, светлая и тёмная тема
static/app.js         ← проверка без перезагрузки, «Показать/Скрыть», «Сгенерировать»
tests/
  reference_set.py    ← Приложение А: 39 паролей с ожиданиями, посчитанными ВРУЧНУЮ
  test_scoring.py     ← юнит-тесты правил
  test_generator.py   ← тесты генерации
  test_api.py         ← интеграционные тесты API и формы
  test_security_perf.py ← пароль не утекает; замеры скорости
scripts/              ← запуск, пересчёт Приложения А, замер скорости
docs/                 ← БТ, СТ, QC, тестирование, эти инструкции
```

Правило слоёв: `scoring.py` и `generator.py` ничего не знают о вебе. `main.py` только принимает запрос, вызывает `evaluate()` / `generate()` и отдаёт ответ. Благодаря этому правила тестируются без сервера (НФТ-10).

## 2. Путь одного запроса

**Через API** (`POST /api/v1/password/check`):

1. FastAPI разбирает JSON по схеме `CheckRequest`. Не строка или нет поля → `on_request_validation_error` → 422 `INVALID_REQUEST`.
2. `check_api()` вызывает `evaluate(password)`.
3. `evaluate()`: `validate()` (NFC, пусто, длина, пробелы) → критерии C1–C6 → штрафы P1, P2 → чёрный список → сумма → нижняя граница 0 → потолок 39 для коротких → уровень → рекомендации.
4. Ошибка валидации → `ValidationError` → `on_validation_error` → 422 с кодом.
5. Middleware `security_headers` добавляет `Cache-Control: no-store` и другие заголовки.

**Через страницу:** `app.js` перехватывает отправку формы и делает тот же запрос к API, поэтому пароль остаётся в поле. Если JS выключен, форма уходит на `POST /check`, сервер рендерит `index.html` с результатом, поле пустое.

## 3. Посмотреть код в работе (VS Code)

1. Откройте папку проекта в VS Code, выберите интерпретатор: Ctrl+Shift+P (Cmd+Shift+P на Mac) → «Python: Select Interpreter» → `.venv`.
2. Поставьте точку останова: щёлкните слева от номера строки в `app/scoring.py`, функция `evaluate`, строка `score = sum(...)`.
3. Запустите отладку: панель «Run and Debug» (Ctrl+Shift+D) → «Запустить сервер (uvicorn, отладка)» → F5.
4. Откройте http://127.0.0.1:8000, проверьте пароль. VS Code остановится на точке: в панели «Variables» видны `passed`, `applied`, `checks`.
5. F10 — шаг, F5 — продолжить.

Тесты: значок колбы слева → «Run Tests». Отладка одного теста — правой кнопкой по нему → «Debug Test». Есть также конфигурация «Тесты: текущий файл».

## 4. Как поменять правило: пример

Задача: минимальная длина 10 вместо 8.

1. **Сначала требования.** Код пишется по СТ: обновите СТ (БП-01, БП-06, табл. 4.2 R-C1) и согласуйте с аналитиком.
2. `app/config.py`: `MIN_GOOD_LENGTH = 10`, текст `"R-C1"` → «…до 10 символов и более.»
3. Запустите `pytest`. Упадут тесты, которые зависят от границы 8: это нормально, они покажут, что изменилось.
4. `python scripts/build_reference.py` покажет строки Приложения А, где ожидание разошлось с кодом.
5. Пересчитайте эти строки **вручную** по алгоритму СТ §5 и исправьте ожидания в `tests/reference_set.py`. Не копируйте вывод кода: тогда тест будет проверять код самим собой.
6. Обновите тесты границ в `test_scoring.py` (`test_criteria`: 9/10 вместо 7/8).
7. `pytest` зелёный → обновите Приложение А в СТ выводом `build_reference.py`.

| Что поменять | Где |
|---|---|
| Баллы критериев | `CRITERIA_POINTS` (сумма должна быть 100, есть проверка `assert`) |
| Пороги уровней, названия | `LEVELS` |
| Список распространённых паролей | `BLACKLIST` (есть `assert len == 20` — поправьте число) |
| Тексты рекомендаций и ошибок | `RECOMMENDATIONS`, `ERRORS` |
| Максимальная длина | `MAX_LENGTH`; подсказка на странице обновится сама |
| Генерация: длина, символы | `GEN_*` |
| Цвета, шрифты | `static/style.css`, переменные в `:root` |
| Тексты на странице | `templates/index.html` |

## 5. Как добавить новый критерий: пример

Задача: критерий C7 «нет даты вида 2024» (−5).

1. СТ: новое БП, рекомендация R-P3, строки Приложения А.
2. `config.py`: `PENALTY_POINTS["P3"] = 5`, текст `"R-P3"`.
3. `scoring.py`: функция `has_year(pwd)` и строка в словаре `applied`.
4. Порядок рекомендаций берётся из порядка ключей словаря — проверьте его по БП-08.
5. Тесты: юнит-тест на `has_year` (граничные значения), строки в `reference_set.py`.
6. Контракт API меняется (появляется P3 в `penalties`) — предупредите тех, кто встроил API.

## 6. Как расширить

| Задача | Подсказка |
|---|---|
| Вызывать API со страницы на другом адресе | `from fastapi.middleware.cors import CORSMiddleware`, `app.add_middleware(CORSMiddleware, allow_origins=["https://ваш-сайт"], allow_methods=["POST"], allow_headers=["Content-Type"])`. Не ставьте `"*"` без необходимости |
| Проверка «на лету» при вводе | в `app.js` слушайте `input` с задержкой 300 мс и вызывайте `check()` |
| Ограничение частоты запросов | вне рамок MVP; обычно делается на прокси (nginx) |
| Перенос оценки в браузер | логику `scoring.py` придётся продублировать на JS — тогда ФТ-07 нужно проверять на двух реализациях |

## 7. Чего нельзя делать (сломает безопасность)

- Не логируйте пароль и тело запроса. Можно логировать уровень (`level`).
- Не выводите пароль в `index.html` (в том числе в `value="..."`).
- Не убирайте обработчик `on_request_validation_error`: стандартный ответ FastAPI возвращает введённый пароль в поле `input`.
- Не используйте `random` для генерации — только `secrets`.
- Не вставляйте данные в страницу через `innerHTML` — только `textContent`.
- Не добавляйте inline-скрипты `<script>...</script>` и стили в атрибутах `onclick`: CSP `default-src 'self'` их заблокирует. JS — только в `static/app.js`.
