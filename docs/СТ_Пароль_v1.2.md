## Глоссарий

Термины БТ v1.0 §2 действуют здесь без изменений. Дополнительно:

| Термин | Определение |
|---|---|
| Символ | Кодовая точка Unicode после нормализации NFC. Длина пароля — число символов |
| NFC | Нормализация Unicode, склеивающая букву и диакритический знак в один символ (e + ◌́ → é) |
| Чёрный список | Технический синоним «списка распространённых паролей» (BLACKLIST в коде) |
| WEAK, MEDIUM, STRONG, VERY_STRONG | Коды уровней «Слабый», «Средний», «Надёжный», «Очень надёжный» |

## 1. Общие сведения

**Назначение:** перевести БТ на язык ИТ: поведение системы, поля, правила, API, интерфейс, НФТ.
**Состав системы:** одно веб-приложение FastAPI; HTML-страница (Jinja2) с JavaScript; JSON API. Без БД и внешних интеграций.

```
Пользователь ──(браузер: форма + app.js)──┐
                                          ├──> FastAPI (main.py) ──> scoring.evaluate() / generator.generate()
Внешняя система ──(HTTP, JSON API)────────┘                              ↑ все правила: config.py
```

### 2.2 UC-01 «Проверить пароль через веб-форму»

| Поле | Значение |
|---|---|
| Актор | Пользователь |
| Предусловие | Система запущена, открыта главная страница |
| Постусловие | Пользователь видит результат; пароль не сохранён на сервере |
| Триггер | Нажатие «Проверить» |

**Основной сценарий (JavaScript включён)**
1. Пользователь открывает главную страницу (ФТ-01).
2. Пользователь вводит пароль и нажимает «Проверить».
3. Браузер отправляет пароль в POST /api/v1/password/check (ФТ-05).
4. Система проверяет входные данные (ФТ-02), рассчитывает оценку (ФТ-03, ФТ-04).
5. Страница показывает балл, уровень, рекомендации без перезагрузки; пароль остаётся в поле.

**Альтернативы**
- 2а. Пользователь нажимает «Показать / Скрыть» (ФТ-09) или «Сгенерировать» (UC-03).
- 3а. JavaScript выключен: форма уходит в POST /check, сервер возвращает страницу с результатом, поле пустое (допущение A-2).

**Исключения**
- 4а. Пустой пароль → «Введите пароль.», результат не показывается.
- 4б. Длина > 64 → «Пароль не должен превышать 64 символов.»
- 4в. Есть пробельный символ → «Пароль не должен содержать пробелы.»
- 4г. Сервер недоступен → «Не удалось связаться с сервером. Повторите попытку.»

### 2.3 UC-02 «Проверить пароль через API»

Актор — внешняя система. POST /api/v1/password/check → валидация → расчёт → 200 + JSON. Исключения: 422 (§6.3).

### 2.4 UC-03 «Сгенерировать пароль»

Актор — пользователь или внешняя система. Пользователь задаёт длину (12–64, по умолчанию 16) и нажимает «Сгенерировать» → браузер вызывает POST /api/v1/password/generate → пароль подставляется в поле → автоматически выполняется UC-01 с шага 3. Исключение: длина вне 12–64 → INVALID_LENGTH.

## 4. Нефункциональные требования

### 4.1 Бизнес-правила

| ID | Правило |
|---|---|
| БП-01 | **Критерии.** C1 «длина ≥ 8» — 25; C2 «длина ≥ 12» — 15; C3 «есть строчная буква» — 15; C4 «есть заглавная буква» — 15; C5 «есть цифра 0–9» — 15; C6 «есть спецсимвол» — 15. Сумма — 100 |
| БП-02 | **Классы символов** (после NFC). Строчная — категория Unicode Ll; заглавная — Lu; цифра — только ASCII 0–9; спецсимвол — символ, категория которого не L* и который не ASCII-цифра. Буквы без регистра (Lt, Lm, Lo, например 字) не дают ни одного класса. Цифры других письменностей (٣) — спецсимволы |
| БП-03 | **Штрафы** (каждый тип — не более одного раза). P1: 3 одинаковых символа подряд, с учётом регистра — −10. P2: 3 символа подряд — только ASCII-латиница (без учёта регистра) или только ASCII-цифры, коды отличаются ровно на +1 или ровно на −1; переходов 9→0 и z→a нет — −10 |
| БП-04 | **Чёрный список.** Если `пароль.lower()` совпадает с элементом — балл 0, WEAK. Список: 123456, 123456789, 12345678, 1234567890, password, password1, qwerty, qwerty123, qwertyuiop, 111111, 000000, 123123, 654321, abc123, 1q2w3e4r, iloveyou, admin, welcome, letmein, passw0rd |
| БП-05 | **Нижняя граница.** Балл = max(0, сумма критериев − штрафы) |
| БП-06 | **Короткий пароль.** Если длина < 8, балл = min(балл, 39). Применяется после штрафов (§5, шаг 6) |
| БП-07 | **Уровни:** 0–39 WEAK «Слабый»; 40–69 MEDIUM «Средний»; 70–89 STRONG «Надёжный»; 90–100 VERY_STRONG «Очень надёжный» |
| БП-08 | **Рекомендации.** Если сработал БП-04 — только R-O1. Иначе — в порядке C1…C6, P1, P2 для каждого невыполненного критерия и применённого штрафа; R-C2 не выводится, если не выполнен C1. Если список пуст — R-OK. Тексты — табл. 4.2 |
| БП-09 | **Ограничения ввода.** Пароль нормализуется NFC. Порядок проверок: (1) длина 0 → EMPTY_PASSWORD; (2) длина > 64 → PASSWORD_TOO_LONG; (3) есть символ, для которого `str.isspace()` истинно → PASSWORD_HAS_WHITESPACE. Пробелы по краям не обрезаются |
| БП-10 | **Генерация.** Длина — целое 12–64, по умолчанию 16. Алфавит: a–z, A–Z, 0–9, `!#$%&*+-=?@^_`. Минимум по одному символу каждого класса. Источник случайности — модуль `secrets`. Кандидат принимается, только если `evaluate()` даёт 100 баллов (до 100 попыток) |

### 4.2 Тексты рекомендаций

| Код | Когда | Текст |
|---|---|---|
| R-C1 | не выполнен C1 | Увеличьте длину пароля до 8 символов и более. |
| R-C2 | не выполнен C2 и выполнен C1 | Для большей надёжности используйте 12 символов и более. |
| R-C3 | не выполнен C3 | Добавьте строчные буквы. |
| R-C4 | не выполнен C4 | Добавьте заглавные буквы. |
| R-C5 | не выполнен C5 | Добавьте цифры. |
| R-C6 | не выполнен C6 | Добавьте спецсимволы, например ! ? # %. |
| R-P1 | применён P1 | Не используйте 3 и более одинаковых символа подряд. |
| R-P2 | применён P2 | Не используйте последовательности вида abc или 123. |

## 5. Алгоритм оценки (ФТ-02…ФТ-04)

1. Нормализация NFC и валидация по БП-09. Ошибка → код ошибки, расчёт не выполняется.
2. Расчёт C1…C6 и P1, P2 — выполняется всегда, результаты попадают в ответ. Поле `points` — баллы критерия/штрафа независимо от шага 3.
3. Если пароль в чёрном списке (БП-04) → балл 0, WEAK, рекомендации [R-O1]. Конец.
4. Балл = сумма баллов выполненных критериев − 10 × число применённых типов штрафов.
5. Балл = max(0, балл) (БП-05).
6. Если длина < 8 → балл = min(балл, 39) (БП-06). Порядок шагов 4–6 менять нельзя: «Aa1!abc» = 39, при потолке до штрафа было бы 29 (Прил. А № 39).
7. Уровень по БП-07.
8. Рекомендации по БП-08.

### 6.2 POST /api/v1/password/check

**Запрос:** `password` — строго string (число, null, массив → INVALID_REQUEST), обязательное; лишние поля игнорируются.

```json
{ "password": "Qwerty789!" }
```

**Ответ 200**

| Поле | Тип | Описание |
|---|---|---|
| score | integer | 0–100 |
| level | string | WEAK / MEDIUM / STRONG / VERY_STRONG |
| level_label | string | «Слабый» / «Средний» / «Надёжный» / «Очень надёжный» |
| length | integer | длина после NFC |
| blacklisted | boolean | сработал БП-04 |
| checks | array | `{code, passed, points}` для C1…C6 в этом порядке |
| penalties | array | `{code, applied, points}` для P1, P2; points = −10 или 0 |
| recommendations | array | `{code, text}` по БП-08 |

```json
{
  "score": 75, "level": "STRONG", "level_label": "Надёжный", "length": 10, "blacklisted": false,
  "checks": [
    {"code": "C1", "passed": true,  "points": 25}, {"code": "C2", "passed": false, "points": 0},
    {"code": "C3", "passed": true,  "points": 15}, {"code": "C4", "passed": true,  "points": 15},
    {"code": "C5", "passed": true,  "points": 15}, {"code": "C6", "passed": true,  "points": 15}
  ],
  "penalties": [
    {"code": "P1", "applied": false, "points": 0}, {"code": "P2", "applied": true, "points": -10}
  ],
  "recommendations": [
    {"code": "R-C2", "text": "Для большей надёжности используйте 12 символов и более."},
    {"code": "R-P2", "text": "Не используйте последовательности вида abc или 123."}
  ]
}
```

Пароль в ответе не возвращается (НФТ-05).

### 6.3 POST /api/v1/password/generate

**Запрос:** `{"length": 20}` — строго integer, необязательное (по умолчанию 16). Тело можно не передавать.
**Ответ 200:** `{"password": "Kip0jg5PMO_PzIqK", "length": 16}`. Это единственный ответ системы, содержащий пароль.

### 6.4 Ошибки

| Код | HTTP (API) | Когда | Текст |
|---|---|---|---|
| EMPTY_PASSWORD | 422 | длина 0 | Введите пароль. |
| PASSWORD_TOO_LONG | 422 | длина > 64 | Пароль не должен превышать 64 символов. |
| PASSWORD_HAS_WHITESPACE | 422 | есть пробельный символ | Пароль не должен содержать пробелы. |
| INVALID_LENGTH | 422 | длина генерации вне 12–64 | Длина пароля для генерации — от 12 до 64 символов. |
| INVALID_REQUEST | 422 | нет поля, неверный тип, тело не JSON | Некорректный запрос. |
| — (только в браузере) | — | сервер недоступен | Не удалось связаться с сервером. Повторите попытку. |

Формат ошибки API: `{"error": {"code": "...", "message": "..."}}`. Заменяет стандартный формат FastAPI, который возвращает введённое значение в поле `input`. В веб-форме ошибка показывается под полем, HTTP 200.
