## 1. Назначение документа

Документ фиксирует цели, задачи и ожидаемые результаты создания системы. Служит основой для спецификации требований (СТ) и приёмочного тестирования (UAT).

## 2. Глоссарий

| Термин | Определение |
|---|---|
| Пароль | Строка, которую пользователь ввёл для проверки или получил при генерации |
| Балл надёжности | Целое число от 0 до 100, результат оценки пароля |
| Уровень надёжности | Одна из 4 градаций: «Слабый», «Средний», «Надёжный», «Очень надёжный» |
| Критерий | Проверяемое свойство пароля, за выполнение которого начисляются баллы (длина, наличие класса символов) |
| Штраф | Свойство пароля, за наличие которого баллы снимаются (повторы, последовательности) |
| Рекомендация | Текст, который сообщает пользователю, что изменить в пароле |
| Список распространённых паролей | Встроенный перечень из 20 паролей, которые считаются скомпрометированными. В СТ и коде — «чёрный список», BLACKLIST |
| Пробельный символ | Пробел, табуляция, неразрывный пробел, перевод строки и другие невидимые разделители |
| Генерация | Создание системой случайного пароля по запросу пользователя |
| Веб-форма | Страница системы в браузере с полем ввода пароля |
| API | Программный интерфейс для вызова проверки и генерации из других систем |

## 3. Бизнес-контекст

**Заказчик:** продуктовая команда онлайн-сервиса. Ей нужен виджет проверки пароля для формы регистрации и тот же сервис в виде API.

**Проблема:** пользователи придумывают короткие пароли из одного типа символов или из списков популярных паролей. Такие пароли подбираются перебором или по словарю, что ведёт к взлому учётных записей. Пользователь сам не может оценить надёжность пароля и не знает, что изменить.

**Цели**

| ID | Цель | Как поймём, что достигнута |
|---|---|---|
| Ц-1 | Пользователь узнаёт уровень надёжности пароля | На эталонном наборе уровень совпадает с ожидаемым в 100 % случаев |
| Ц-2 | Пользователь знает, как усилить пароль | Для каждого невыполненного критерия и штрафа выводится рекомендация |
| Ц-3 | Проверку можно встроить в другие системы | API отвечает по контракту из СТ |
| Ц-4 | Пароль не утекает | Пароль не найден в журналах, файлах, ответах сервера после прогона тестов |
| Ц-5 | Пользователь может получить надёжный пароль, не придумывая его | Сгенерированный пароль получает уровень «Очень надёжный» |

**Стейкхолдеры**

| Стейкхолдер | Интерес |
|---|---|
| Продуктовая команда (Заказчик) | Меньше слабых паролей при регистрации, готовый виджет и API |
| Пользователь | Быстро понять, годится ли пароль, и что изменить |
| Разработчики формы регистрации | Встроить проверку через API |
| Команда разработки | Однозначные требования, которые можно проверить |

## 4. Бизнес-требования

| ID | Требование | Источник (кто / зачем) | Критерий проверки | Цель |
|---|---|---|---|---|
| БТ-01 | Система должна оценивать введённый пароль баллом от 0 до 100 и одним из 4 уровней надёжности: «Слабый», «Средний», «Надёжный», «Очень надёжный» | Продуктовая команда / пользователь должен понять, годится ли пароль | Для каждого пароля эталонного набора (Приложение А к СТ) балл и уровень совпадают с ожидаемыми | Ц-1 |
| БТ-02 | Оценка должна выполняться по правилам Приложения Б: длина, наличие строчных и заглавных букв, цифр, спецсимволов; штрафы за повторы и последовательности | Продуктовая команда / единые правила для формы и API | Правила в СТ совпадают с Приложением Б; эталонный набор проходит | Ц-1 |
| БТ-03 | Пароль из списка распространённых паролей должен получать балл 0 и уровень «Слабый» независимо от длины и состава символов | Продуктовая команда / словарные пароли подбираются первыми | Все 20 паролей списка в нижнем, верхнем и смешанном регистре получают балл 0 и уровень «Слабый» | Ц-1 |
| БТ-04 | Система должна выдавать рекомендации по правилу п. 13 Приложения Б: по одной на каждый невыполненный критерий и применённый штраф; для пароля из списка распространённых — одну рекомендацию заменить пароль; если замечаний нет — сообщение, что пароль соответствует всем критериям | Продуктовая команда / пользователь должен знать, как усилить пароль | Для паролей эталонного набора состав и порядок рекомендаций совпадают с ожидаемыми | Ц-2 |
| БТ-05 | Проверка должна быть доступна через веб-форму в браузере без установки ПО и без регистрации | Пользователь / проверить пароль без лишних шагов | Пользователь открывает адрес системы в Chrome, Firefox или Edge последней версии и получает результат без входа в систему | Ц-1, Ц-2 |
| БТ-06 | Проверка и генерация должны быть доступны через API | Разработчики формы регистрации / встроить проверку в свою форму | Вызов API по контракту СТ возвращает тот же балл, уровень и рекомендации, что и веб-форма | Ц-3 |
| БТ-07 | Система не должна сохранять пароль на сервере: в журналах, файлах, кеше | Продуктовая команда / исключить утечку паролей | После прогона всех тестов тестовые пароли не найдены в журналах сервера; ответы сервера запрещают кеширование | Ц-4 |
| БТ-08 | Пользователь должен получать результат проверки не позднее чем через 1 секунду после нажатия кнопки «Проверить» | Пользователь / не ждать результата | Локальный запуск на компьютере разработчика: 20 проверок подряд, каждая ≤ 1 с | Ц-1 |
| БТ-09 | Система не должна передавать пароль внешним сервисам | Продуктовая команда / пароль не покидает систему | Браузер отправляет пароль только на адрес самой системы; сервер не выполняет сетевых запросов | Ц-4 |
| БТ-10 | После проверки введённый пароль должен оставаться в поле ввода, чтобы пользователь мог исправить его по рекомендациям | Продуктовая команда (решение по в.2) / меньше повторного ввода | После нажатия «Проверить» поле содержит введённый пароль (в браузере с включённым JavaScript) | Ц-2 |
| БТ-11 | Пользователь должен иметь возможность показать и скрыть введённый пароль | Продуктовая команда (решение по в.3) / проверить, что пароль набран без опечаток | Кнопка «Показать / Скрыть» переключает отображение без отправки пароля на сервер | Ц-2 |
| БТ-12 | Система должна по запросу пользователя генерировать случайный пароль, который по правилам Приложения Б получает 100 баллов | Продуктовая команда (решение по в.9) / дать пользователю готовый надёжный пароль | 1000 сгенерированных паролей: все получают 100 баллов, повторов нет | Ц-5 |
| БТ-13 | Система должна отклонять пароль, который пустой, длиннее 64 символов или содержит пробельный символ, и сообщать причину | Продуктовая команда (решения по в.4, в.7) / единые ограничения пароля в сервисе | Для каждого случая выводится своё сообщение, оценка не выполняется | Ц-1 |
| БТ-14 | Система должна быть доступна в интернете по постоянному адресу с HTTPS | Заказчик (CR-01) / показать работу проверяющим без локальной установки | Адрес https://password-check-b21c.onrender.com открывается из внешней сети; /health отвечает 200; страница загружается по HTTPS | Ц-1, Ц-3 |
| БТ-15 | На странице должна быть ссылка на репозиторий с исходным кодом и документацией | Заказчик (CR-01) / проверяющие видят код и документы проекта | Ссылка в нижней части страницы открывает https://github.com/Cloncher-code/password_check | Ц-3 |

## 5. Бизнес-правила оценки (Приложение Б)

| № | Правило | Значение |
|---|---|---|
| 1 | Минимальная длина для критерия | 8 символов |
| 2 | Рекомендуемая длина | 12 символов |
| 3 | Длина ввода | от 1 до 64 символов |
| 4 | Пробельные символы | запрещены (любые, см. глоссарий) |
| 5 | Классы символов | строчные буквы, заглавные буквы (любой алфавит, кириллица считается), цифры 0–9, спецсимволы (всё, что не буква и не цифра 0–9) |
| 6 | Баллы | длина ≥ 8 — 25; длина ≥ 12 — 15; каждый из 4 классов символов — по 15. Сумма — 100 |
| 7 | Повторы | 3 и более одинаковых символа подряд: −10 баллов |
| 8 | Последовательности | 3 символа подряд по алфавиту (латиница) или по порядку цифр, в прямом или обратном направлении («abc», «321»): −10 баллов. Переход «z→a», «9→0» последовательностью не считается |
| 9 | Повторный штраф | каждый тип штрафа применяется не более одного раза |
| 10 | Список распространённых паролей | 20 паролей, перечень в СТ (БП-04); сравнение без учёта регистра |
| 11 | Короткий пароль | пароль короче 8 символов не может получить больше 39 баллов («Слабый») |
| 12 | Пороги уровней | 0–39 «Слабый», 40–69 «Средний», 70–89 «Надёжный», 90–100 «Очень надёжный» |
| 13 | Рекомендации | по одной на каждый невыполненный критерий и штраф; рекомендация о 12 символах не выводится, пока не выполнена длина 8; для пароля из списка — только «замените пароль» |
| 14 | Генерация | длина от 12 до 64, по умолчанию 16; символы: латинские буквы, цифры, спецсимволы `!#$%&*+-=?@^_` |

## 6. Вне рамок

Хранение паролей и истории проверок; регистрация и авторизация; проверка по внешним базам утечек; мультиязычность; ограничение частоты запросов; вызов API со страниц на других адресах (CORS).

## 7. Допущения и ограничения

- Локальный запуск и публичный стенд на Render (бесплатный тариф): после 15 минут без запросов сервис засыпает, первый запрос после паузы — около минуты.
- Нагрузка: единицы пользователей одновременно; ограничение частоты запросов вне рамок.
- Стек: Python 3.11–3.13, FastAPI, Uvicorn, Jinja2, HTML5, CSS, JavaScript без сторонних библиотек.
- База данных не используется.
