## 1. Назначение документа

Документ фиксирует цели, задачи и ожидаемые результаты создания системы. Служит основой для спецификации требований (СТ) и приёмочного тестирования (UAT).

## 2. Глоссарий

| Термин | Определение |
|---|---|
| Пароль | Строка, введённая пользователем для проверки |
| Балл надёжности | Целое число от 0 до 100, результат оценки пароля |
| Уровень надёжности | Одна из 4 градаций: «Слабый», «Средний», «Надёжный», «Очень надёжный» |
| Критерий | Проверяемое свойство пароля (длина, наличие класса символов) |
| Рекомендация | Текст, который сообщает пользователю, что изменить в пароле |
| Список распространённых паролей | Встроенный в систему перечень паролей, которые считаются скомпрометированными |
| API | Программный интерфейс для вызова проверки из других систем |

## 3. Бизнес-контекст

Кратко из документа 01: проблема, цели Ц-1…Ц-4, стейкхолдеры, границы.

## 4. Бизнес-требования

Формат: одно требование — одна мысль; у каждого источник и критерий проверки.

| ID | Требование | Источник (кто / зачем) | Критерий проверки | Цель |
|---|---|---|---|---|
| БТ-01 | Система должна оценивать введённый пароль баллом от 0 до 100 и одним из 4 уровней надёжности: «Слабый», «Средний», «Надёжный», «Очень надёжный» | Служба ИБ / пользователь должен понять, годится ли пароль | Для каждого пароля из эталонного набора (Приложение А к СТ) балл и уровень совпадают с ожидаемыми | Ц-1 |
| БТ-02 | Оценка должна выполняться по правилам из Приложения Б, утверждённым Заказчиком: длина пароля, наличие строчных и заглавных букв, цифр, спецсимволов, отсутствие повторов и последовательностей | Служба ИБ / единые правила для всех систем компании | Правила в СТ совпадают с Приложением Б; эталонный набор проходит | Ц-1 |
| БТ-03 | Пароль, который входит в список распространённых паролей, должен получать уровень «Слабый» независимо от длины и состава символов | Служба ИБ / словарные пароли подбираются первыми | Все пароли списка в любом регистре получают уровень «Слабый» | Ц-1 |
| БТ-04 | Для каждого невыполненного критерия система должна выдавать рекомендацию, что изменить в пароле | Служба ИБ / пользователь должен знать, как усилить пароль | Для паролей эталонного набора список рекомендаций совпадает с ожидаемым | Ц-2 |
| БТ-05 | Проверка должна быть доступна через веб-форму в браузере без установки ПО и без регистрации | Пользователь / проверить пароль без лишних шагов | Пользователь открывает адрес системы и получает результат без входа в систему | Ц-1, Ц-2 |
| БТ-06 | Проверка должна быть доступна через API для вызова из других систем | Разработчики внешних систем / встроить проверку в формы регистрации | Вызов API по контракту из СТ возвращает тот же балл, уровень и рекомендации, что и веб-форма | Ц-3 |
| БТ-07 | Система не должна сохранять введённый пароль и передавать его за пределы системы | Служба ИБ / исключить утечку паролей | После прогона всех тестов пароль не найден в логах, файлах и ответах, кроме поля ввода на стороне пользователя ⚑ | Ц-4 |
| БТ-08 | Пользователь должен получать результат проверки не позднее чем через 1 секунду после нажатия кнопки «Проверить» | Пользователь / не ждать результата | Замер на учебном стенде: 20 проверок подряд, каждая ≤ 1 с | Ц-1 |

## 5. Бизнес-правила оценки (Приложение Б) ⚑ утвердить

| № | Правило | Значение |
|---|---|---|
| 1 | Минимальная длина | 8 символов |
| 2 | Рекомендуемая длина | 12 символов |
| 3 | Максимальная длина | 128 символов ⚑ (защита от перегрузки) |
| 4 | Классы символов | строчные буквы, заглавные буквы, цифры, спецсимволы |
| 5 | Повторы | 3 и более одинаковых символа подряд снижают оценку |
| 6 | Последовательности | 3 и более символа по алфавиту или по порядку цифр («abc», «321») снижают оценку |
| 7 | Список распространённых паролей | 20 паролей, перечень в СТ ⚑ |
| 8 | Короткий пароль | пароль короче 8 символов не может получить уровень выше «Слабый» |
| 9 | Пороги уровней | 0–39 «Слабый», 40–69 «Средний», 70–89 «Надёжный», 90–100 «Очень надёжный» ⚑ |

## 6. Вне рамок

Хранение паролей и истории проверок; регистрация и авторизация; проверка по внешним базам утечек; генерация паролей; мультиязычность; ограничение частоты запросов.

## 7. Допущения и ограничения

- Стек: Python 3.1x, FastAPI, Uvicorn, Jinja2, HTML5, CSS, JS — при необходимости.
- База данных не используется.
