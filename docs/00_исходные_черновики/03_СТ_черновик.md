## 2. Пользовательские требования

### 2.1 User stories

| ID | User story | Критерии приёмки | БТ |
|---|---|---|---|
| US-01 | Как пользователь, который придумывает пароль, я хочу узнать уровень его надёжности, чтобы не использовать легко подбираемый пароль | Дано: открыта форма. Когда: ввожу пароль и нажимаю «Проверить». Тогда: вижу балл 0–100 и уровень | БТ-01, БТ-02, БТ-03, БТ-05 |
| US-02 | Как пользователь, я хочу видеть, что именно исправить в пароле, чтобы усилить его | Тогда: вижу список рекомендаций по невыполненным критериям | БТ-04 |
| US-03 | Как разработчик внешней системы, я хочу вызвать проверку через API, чтобы встроить её в форму регистрации | Дано: POST-запрос по контракту. Тогда: получаю JSON с баллом, уровнем, рекомендациями | БТ-06 |

### 2.2 Use case UC-01 «Проверить пароль через веб-форму»

| Поле | Значение |
|---|---|
| Актор | Пользователь |
| Цель | Получить оценку пароля и рекомендации |
| Предусловие | Система запущена, пользователь открыл главную страницу |
| Постусловие | Пользователь видит результат; пароль не сохранён в системе |
| Триггер | Нажатие кнопки «Проверить» |

**Основной сценарий**
1. Пользователь открывает главную страницу.
2. Система показывает форму с полем «Пароль» и кнопкой «Проверить».
3. Пользователь вводит пароль и нажимает «Проверить».
4. Система проверяет входные данные (ФТ-02).
5. Система рассчитывает оценку (ФТ-03).
6. Система показывает балл, уровень и рекомендации (ФТ-04).

**Альтернативы**
- 3а. Пользователь нажимает «Показать» — поле отображает пароль открытым текстом; повторное нажатие скрывает ⚑.

**Исключения**
- 4а. Пароль пустой → сообщение «Введите пароль.», результат не показывается.
- 4б. Длина больше 128 символов → сообщение «Пароль не должен превышать 128 символов.», результат не показывается.

### 2.3 Use case UC-02 «Проверить пароль через API»

Актор — внешняя система. Основной сценарий: POST /api/v1/password/check → валидация → расчёт → 200 + JSON. Исключения: 422 с кодом ошибки (раздел 6.3).

## 4. Нефункциональные требования

### 4.1 Бизнес-правила оценки

| ID | Правило |
|---|---|
| БП-01 | **Критерии** (каждый выполненный даёт баллы): C1 «длина ≥ 8» — 25; C2 «длина ≥ 12» — 15; C3 «есть строчная буква» — 15; C4 «есть заглавная буква» — 15; C5 «есть цифра 0–9» — 15; C6 «есть спецсимвол» — 15. Сумма максимум 100 |
| БП-02 | **Классы символов.** Строчная / заглавная буква — любой буквенный символ Unicode в нижнем / верхнем регистре (кириллица считается). Цифра — только ASCII 0–9. Спецсимвол — любой символ, который не буква и не ASCII-цифра, включая пробел |
| БП-03 | **Штрафы** (каждый тип — не более одного раза): P1 «3+ одинаковых символа подряд, с учётом регистра» — −10; P2 «3 символа подряд образуют возрастающую или убывающую последовательность с шагом 1: только латинские буквы без учёта регистра или только цифры; без перехода 9→0 и z→a» — −10 |
| БП-04 | **Чёрный список.** Если пароль без учёта регистра совпадает с элементом списка — балл 0, уровень «Слабый». Список: 123456, 123456789, 12345678, 1234567890, password, password1, qwerty, qwerty123, qwertyuiop, 111111, 000000, 123123, 654321, abc123, 1q2w3e4r, iloveyou, admin, welcome, letmein, passw0rd ⚑ |
| БП-05 | **Нижняя граница.** Балл = max(0, сумма критериев − штрафы) |
| БП-06 | **Короткий пароль.** Если длина < 8, балл = min(балл, 39) |
| БП-07 | **Уровни:** 0–39 WEAK «Слабый»; 40–69 MEDIUM «Средний»; 70–89 STRONG «Надёжный»; 90–100 VERY_STRONG «Очень надёжный» |
| БП-08 | **Рекомендации.** Если сработал БП-04 — только R-O1. Иначе — по порядку C1…C6, P1, P2 для каждого невыполненного критерия и применённого штрафа; R-C2 не выводится, если не выполнен C1. Если список пуст — R-OK. Тексты — таблица 4.2 |

### 4.2 Тексты рекомендаций

| Код | Когда | Текст |
|---|---|---|
| R-C1 | не выполнен C1 | Увеличьте длину пароля до 8 символов и более. |
| R-C2 | не выполнен C2 (и выполнен C1) | Для большей надёжности используйте 12 символов и более. |
| R-C3 | не выполнен C3 | Добавьте строчные буквы. |
| R-C4 | не выполнен C4 | Добавьте заглавные буквы. |
| R-C5 | не выполнен C5 | Добавьте цифры. |
| R-C6 | не выполнен C6 | Добавьте спецсимволы, например ! ? # % или пробел. |
| R-P1 | применён P1 | Не используйте 3 и более одинаковых символа подряд. |
| R-P2 | применён P2 | Не используйте последовательности вида abc или 123. |
| R-O1 | сработал БП-04 | Этот пароль входит в список распространённых. Придумайте другой. |
| R-OK | рекомендаций нет | Пароль соответствует всем критериям. |

## 5. Алгоритм оценки (ФТ-03, ФТ-04)

1. Валидация (ФТ-02). Ошибка → ответ с кодом ошибки, расчёт не выполняется.
2. Расчёт критериев C1…C6 и штрафов P1, P2 (выполняется всегда, результаты попадают в ответ).
3. Если пароль в чёрном списке (БП-04) → балл 0, уровень WEAK, рекомендации [R-O1]. Конец.
4. Балл = сумма баллов выполненных критериев − 10 × число применённых типов штрафов.
5. Балл = max(0, балл) (БП-05).
6. Если длина < 8 → балл = min(балл, 39) (БП-06).
7. Уровень по БП-07.
8. Рекомендации по БП-08.

### 6.2 POST /api/v1/password/check

**Запрос**
| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| password | string | да | длина 1–128 символов Unicode |

```json
{ "password": "Qwerty789!" }
```

**Ответ 200**
| Поле | Тип | Описание |
|---|---|---|
| score | integer | 0–100 |
| level | string | WEAK / MEDIUM / STRONG / VERY_STRONG |
| level_label | string | «Слабый» / «Средний» / «Надёжный» / «Очень надёжный» |
| length | integer | длина пароля |
| blacklisted | boolean | сработал БП-04 |
| checks | array | `{code, passed, points}` для C1…C6 |
| penalties | array | `{code, applied, points}` для P1, P2 |
| recommendations | array | `{code, text}` по БП-08 |

```json
{
  "score": 75,
  "level": "STRONG",
  "level_label": "Надёжный",
  "length": 10,
  "blacklisted": false,
  "checks": [
    {"code": "C1", "passed": true,  "points": 25},
    {"code": "C2", "passed": false, "points": 0},
    {"code": "C3", "passed": true,  "points": 15},
    {"code": "C4", "passed": true,  "points": 15},
    {"code": "C5", "passed": true,  "points": 15},
    {"code": "C6", "passed": true,  "points": 15}
  ],
  "penalties": [
    {"code": "P1", "applied": false, "points": 0},
    {"code": "P2", "applied": true,  "points": -10}
  ],
  "recommendations": [
    {"code": "R-C2", "text": "Для большей надёжности используйте 12 символов и более."},
    {"code": "R-P2", "text": "Не используйте последовательности вида abc или 123."}
  ]
}
```
Пароль в ответе не возвращается (НФТ-05).

### 6.3 Ошибки

| Код | HTTP (API) | Когда | Текст |
|---|---|---|---|
| EMPTY_PASSWORD | 422 | длина 0 | Введите пароль. |
| PASSWORD_TOO_LONG | 422 | длина > 128 | Пароль не должен превышать 128 символов. |
| INVALID_REQUEST | 422 | нет поля password, не строка, тело не JSON | Некорректный запрос. |

Формат ошибки API: `{"error": {"code": "EMPTY_PASSWORD", "message": "Введите пароль."}}` — заменяет стандартный формат ошибок FastAPI.
В веб-форме ошибка показывается под полем (НФТ-08), HTTP 200.
