## BUG-04, BUG-05 (найдены при первом запуске на macOS, 26.10.2026)

| Поле | BUG-04 | BUG-05 |
|---|---|---|
| Заголовок | Сервер бесконечно перезапускается сразу после `run_mac.sh` | Скрипт создаёт окружение на Python 3.9 вместо 3.11+ |
| Требование | НФТ-03 (запуск одной командой) | НФТ-01 (Python 3.11–3.13) |
| Критичность | major | major |
| Тип | дефект скрипта запуска | дефект скрипта запуска |
| Шаги | 1. Проект в `~/Documents` (iCloud). 2. `bash scripts/run_mac.sh` | 1. macOS с системным `python3` 3.9. 2. `bash scripts/run_mac.sh` |
| Ожидаемый результат | сервер запущен один раз | окружение на Python 3.11+ или понятная ошибка |
| Фактический результат | `WatchFiles detected changes in '.venv/...'. Reloading...` десятки раз | `.venv/lib/python3.9/...` |
| Причина | `--reload` в uvicorn всегда следит за текущей папкой, включая `.venv`; `--reload-dir` это не отключает; `--reload-exclude` работает только с абсолютным путём (проверено по исходникам uvicorn 0.32.1) | скрипт вызывал `python3` без проверки версии |
| Окружение | macOS, Apple Silicon, Homebrew | то же |
| Исправление | скрипты запуска без `--reload`; для разработки — `--reload-exclude` с абсолютным путём к `.venv` (launch.json, инструкция 1). Проверено: 3 правки в `.venv` — 0 перезапусков, правка `app/` — 1 | скрипт ищет python3.13 → 3.12 → 3.11, пересоздаёт `.venv` на старом Python, иначе выводит команду установки |
| Статус | исправлен → ждёт проверки на Mac Андрея | исправлен → ждёт проверки на Mac Андрея |
